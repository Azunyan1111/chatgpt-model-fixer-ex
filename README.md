# chatgpt-model-fixer-ex

ChatGPTのChat／Codexモードごとに選んだモデルと努力量を別々に保存し、再読み込みや新しいタブでも自動的に選択します。現在のChatGPT画面ではCodexモードが「Work」と表示されます。

Chromeの拡張機能管理画面でデベロッパーモードを有効にし、「パッケージ化されていない拡張機能を読み込む」からこのディレクトリを選択してください。

モード、モデル、努力量はすべて画面操作で選択し、URLパラメーターの書き換えやページの再読み込みは行いません。Chat／Codexモードは `aria-pressed` を持つ切替ボタンを押して復元し、モデル選択ボタンの `data-composer-navigation-target="reasoning"`、モデル一覧の `role="menuitemradio"`、スライダーの `aria-valuenow` を使用してモデルと努力量を復元します。モードを切り替えた直後はモデル選択ボタンが置き換わるため、新しいボタンが落ち着いてからモデルと努力量を復元します。保存した選択肢が現在の画面にない場合は、その項目を変更しません。

URLパラメーターは使用しません。以前は `surface=work` を付けて再読み込みすることでCodexモードを開いていましたが、ページを開くたびに再読み込みが発生して煩わしく、また表示名から作った `model=gpt-5.6-sol` のような値をChatGPTは認識せず、読み取った後にURLから取り除いてモデルを既定値へ戻すため、画面操作で選んだモデルを上書きしてしまうからです。

会話を開いたり画面左上の「新しいチャット」を押したりしてページ内で遷移すると、ChatGPTは描画されなくなった直前の入力欄のモデル選択ボタンをDOMに残したまま新しいボタンを追加します。拡張機能は描画中（`getClientRects()` が空でない）のモデル選択ボタンだけを使用し、残された見えないボタンのメニューは開きません。

ChatGPTは画面の初期化が終わるまで操作を受け付けないため、モデルメニューを開く操作とモード切替は反映されるまで繰り返します。Codexモードでは、読み込み直後にChatのモデル一覧を持つモデル選択ボタンを一瞬だけ表示してから置き換えるため、モデル選択ボタンが0.5秒間置き換わらなかったときだけ復元します。URLやモデル選択ボタンが変わったときは選択をやり直します。復元中にモデル選択ボタン、モデルメニュー、モード切替をユーザーが押した場合は復元を中断し、ユーザーの操作を優先します。ユーザーがメニューを開いている間は復元を始めず、閉じた後に復元します。努力量は、スライダーの値が実際に変わったときだけ保存し、メニューを開いただけでは保存しません。何も保存していない間はメニューを開きません。

## テスト

Node.js 22とpnpmを用意し、次のコマンドを実行します。

```sh
pnpm install --frozen-lockfile
pnpm exec patchright install chromium
pnpm run test
```

`pnpm run test:unit` は純粋なロジックだけ、`pnpm run test:live` は実際のChatGPTでのテストだけを実行します。実ページのテストはモード・モデル・努力量の組み合わせごとに分かれているため、失敗した組み合わせだけを名前で指定して再実行できます。名前の指定はファイルより前に置きます。

```sh
node --test --test-name-pattern="Codex／デフォルト／努力量1" test/live.test.js
```

実行時依存はありません。開発時のみ、Playwright互換のpatchrightを使用します。Playwrightが操作するChromiumは、CDP経由で `navigator.webdriver` が真になるなどの痕跡からChatGPTのCloudflareの確認画面で止まるため、同じChromiumを痕跡を残さずに操作するpatchrightを使用します。初回のテストだけ、macOS版Chromeの `Default` プロファイルからChatGPTのセッションに必要なデータをGit管理外の `.chrome-profile/` へ複製し、その複製を積んだChromeでセッションを読み取ります。元のChromeプロファイルは変更しません。

現在のGoogle Chromeは未パッケージ拡張機能を読み込むコマンドライン引数を受け付けないため、復号済みのセッションを、拡張機能を読み込んだPlaywright同梱Chromiumの `.chromium-profile/` へ渡して `https://chatgpt.com/` を操作します。

2回目以降のテストは `.chromium-profile/` をそのまま再利用し、マシンのChromeプロファイル、Chrome本体、キーチェーンには触れません。`.chromium-profile/` がなく `.chrome-profile/` だけがある場合は、マシンのChromeから複製し直さず、既存の `.chrome-profile/` からセッションを読み取ります。セッションの期限が切れたときは、両方のディレクトリを削除してからテストを実行すると、もう一度だけ複製します。

ChromeとChromiumはどちらもヘッドレスで起動します。ヘッドレス版のUser-Agentに含まれる `HeadlessChrome` のままではChatGPTがCloudflareの確認画面から進まないため、各ブラウザーの実際のUser-Agentを取得し、`HeadlessChrome` を `Chrome` に置き換えて使用します。

テストは実ページに表示されたChat／Codexそれぞれのモデルと努力量の範囲を実行時に取得し、組み合わせごとのテストで保存・再読み込み・復元できることを検証します。再読み込みやモード切替の後は、コンテンツスクリプトの分離環境にある `ChatGPTModelFixer.isSettled()` が0.5秒間続けて真になり、拡張機能の復元が終わったことを確認してから画面を読み取ります。ChatGPTは再読み込み後に、CodexモードのままChatのモデル一覧を出し続けることがあるため、表示中のモデル一覧が実行時に取得した一覧と一致するまで最大3回再読み込みします。読み取り中にChatGPTがモデル選択ボタンを置き換えてメニューが消えた場合は、復元の完了を待って読み取りをやり直します。努力量を変えるキー操作が3秒以内に反映されない場合は一度だけ押し直し、それでも変わらなければ画面の状態を添えて失敗にします。会話を開いてから「新しいチャット」を押す遷移でも保存した設定が復元され、見えないモデル選択ボタンのメニューが開いたままにならないことも検証します。モック、ローカルの代替画面、固定したモデル一覧は使用しません。保存キーの決定などの純粋なロジックと、URLの書き換えや再読み込みをコードが含まないことは、Node.js標準のテストランナーで検証します。GitHub Actionsではログインできないため、このテストはローカルで実行します。
